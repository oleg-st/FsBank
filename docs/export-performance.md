# Export performance, 2026-09-24

Measured in Release on saved captures: 482 items across equipped, inventory and
seven bank tabs. The combined diagnostic `full.json` is about 163 MB. No game
input or OCR was performed by the export benchmark.

Three runs per mode:

| Stage | Before | After |
| --- | --- | --- |
| Compact export, after OCR/report generation | 7.58–8.40 s | 0.003–0.011 s |
| Debug export, after OCR/report generation | 7.78–8.40 s | 1.63–1.70 s |
| Temporary capture cleanup | 0.33–0.39 s | 0.16–0.30 s |
| Initial batch report generation | Not separately measured | 0.81–2.14 s |

These are local, cached-file measurements, not an end-to-end scan guarantee.
The UI's “Saving results” phase also includes draining pending OCR and writing
session reports. Those costs depend on the scan and are not included in the
export timings above. Debug export still copies all capture/diagnostic files.

Previously `OcrPipeline.Complete` assembled the batch, then `ScanExport.Complete`
assembled it again. Compact export subsequently parsed the large report and
projected all items yet again. Thus disabling diagnostic output did not avoid
processing the temporary `full.json`.

The export now reuses completed batch artifacts and copies the existing compact
files. Result detection checks PNG names and small session metadata before large
reports. Batch generation streams diagnostic rows into a temporary file, retains
only compact item projections, and replaces the full report after successful
completion. It avoids cloning the complete OCR JSON tree and serializing each
diagnostic row again solely to project compact fields. This removes redundant
work without additional concurrent disk operations.

The technical log now separates OCR drain, per-session reports, batch reports,
result detection, file copy, scan summary/issues, and temporary cleanup.
`pipeline.json` also records `drainSeconds` and per-session `reportSeconds`.

Validation: Release build; export, UI and OCR pipeline checks; cancelled merge
preserves the previous report and removes its temporary output. Benchmark checks
compact JSON/browser agreement on every run and full diagnostic JSON equivalence
on the first run of each mode. Full comparison used the baseline generated by
the pre-optimization code, because the older fixture uses an older summary schema.

Reproduce with a saved batch generated using the current report schema:

```powershell
dotnet build src/FsBank.Scanner.Diagnostics -c Release --no-restore
dotnet src/FsBank.Scanner.Diagnostics/bin/Release/net10.0-windows/FsBank.Scanner.Diagnostics.dll --benchmark-export <saved-batch> <new-output-folder>
```

The benchmark copies the source outside the timed region, measures batch assembly,
export and cleanup separately, checks output equivalence, and writes `timings.json`.
It leaves exported copies in the output folder; allow space for three debug exports.
